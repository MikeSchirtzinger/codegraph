    The stated mechanism was wrong and the first fix made it worse, which is
    recorded because the change that landed is not the change that was
    specified. L9 attributed the cost to SQL parsing: 250 concatenated UPDATE
    statements per chunk against one bulk INSERT. Rewriting those as a single
    server-side FOR loop over a bound array collapsed 4,458 parses into 18 and
    moved instructions retired from 195.5B to 306.2B, 1.57x the wrong way. Wall
    time fell, but machine load fell with it, so only the instruction count is
    trustworthy. A conditional UPDATE has to find its rows, so N updates over an
    N-edge table is quadratic: 4,458 squared is 19.9M row visits, which at
    roughly 10k instructions each is about 200B and matches what was measured.
    Parsing was never the dominant cost.

    stored values verbatim, resolution_gen included, and selectivity still means

    rather than the lookup key alone. write_file_refs went from one CREATE per
    cross-file pair to a chunked bulk INSERT. write_updates and EdgeUpdate are
    deleted.
